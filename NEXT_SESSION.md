# Następna sesja — TimonConfigs

1. Zacznij od git status i aktualnego `main`. Bieżące wersje to theme **0.9.0 / Core 0.7.0**. Przeczytaj `PROGRESS.md`, `docs/MEMBER_DASHBOARD_0.9.md`, `docs/MEMBER_LIBRARY_0.8.md` oraz `docs/ASTRA_MEMBER_UX_HANDOFF.md`. Zachowaj istniejący CPT `tc_config`, treści, konfigurację płatności i poprawkę Home. Nie twórz projektu od nowa ani nie powtarzaj ukończonego etapu UI.
2. Kod biblioteki członka jest zaimplementowany lokalnie: wiele prywatnych plików, katalog/sortowanie, OAuth i aktualne role, Profile/My Downloads, Browse Memberships, podpisane jednorazowe pobieranie. OAuth jest domyślnie OFF; testy używają mocków HTTP Discorda. Nie deklaruj działania na prawdziwym koncie lub produkcji.
3. Następny priorytet: izolowany HTTPS staging, rzeczywiste Discord client ID/secret, guild ID i niezmienione Free/Monthly/Lifetime role IDs. Sekret wpisz w panelu lub wp-config, nigdy w repo/chat/log. Ustaw `WP_ENVIRONMENT_TYPE=staging`, zarejestruj dokładny callback z Settings → Discord membership i wykonaj realne testy OAuth, ról, refresh/logout, odebrania roli, wygaśnięcia i cache. Dopiero po tym potwierdź gotowość produkcyjną. PKCE wymaga sprawdzenia faktycznego wsparcia aplikacji.
4. Hostinger: potwierdź katalog prywatny poza wszystkimi publicznymi rootami, prawa właściciela PHP, OpenSSL/fileinfo, PHP upload/post limity i politykę skanera. ZNBK/XIMMR wymagają zatwierdzonego inspektora; ZIP jest odrzucony. Wyklucz account/my-downloads/admin-post i query OAuth/download z CDN/page cache. Nie zastępuj Security Bot, Ticket Tool ani automatyki Upgrade.chat.
5. Właściciel nadal musi dostarczyć rzeczywiste Monthly/Lifetime checkout URLs, support email/social links, prawidłowe przypisanie trzech filmów Apex do urządzeń, oryginalne assety i zatwierdzone treści prawne. Nie publikuj niezweryfikowanych konfiguracji/demonstracyjnych opinii. Drafty Apex pozostają draftami.
6. Lokalnie: `bash tools/setup-local-wordpress.sh` uruchamia WordPress i prywatny wolumen, zachowuje istniejące treści/statusy i sprawdza 27 tras. Narzędzia → TimonConfigs setup tworzy brakujące strony członka także po aktualizacji aktywnej wtyczki. Własne Account strony zachowują treść — wstaw właściwy shortcode ręcznie, jeśli potrzeba.
7. Testy według faktycznej zmiany: `discord`, `private-files`, `downloads`, `catalog`, `seo`, `video`, `site`, `blocks`, `editorial`, `checkout` przez WP-CLI eval-file. `member-catalog` wymaga `--skip-plugins=timonconfigs-core`; na końcu przywróć prawidłowe reguły permalinków. Przeglądarka: `member-area-browser.cjs`, `private-files-browser.cjs`, `download-stream.cjs`, istniejące storefront/website. Mutujące skrypty tylko na disposable localhost:8080. Nie wykonuj zakupów. Nowy test `member-ui-integration.php` zapisuje JSON do `artifacts/member-ui-render.json`; potem uruchom `node tests/member-ui-states-browser.cjs`. To rzeczywisty renderer PHP z mockiem zewnętrznego transportu, nie dowód działania prawdziwego OAuth.
8. Screenshot `wp-content/themes/timonconfigs/screenshot.png` ma dokładnie 1200×900 i pochodzi z rzeczywistego renderu WP w udokumentowanym kompaktowym trybie browser-only. Pełne nietknięte screenshoty 1440/390 są w artifacts. Nie zastępuj go samym tłem.
9. Przygotowane paczki: `artifacts/timonconfigs-theme-0.9.0.zip`, `artifacts/timonconfigs-core-0.7.0.zip`; sprawdź manifest i raport przed użyciem. Backup lokalnej bazy/źródeł: ignorowane `artifacts/backups/member-library-*`; wolumen prywatnych plików musi być backupowany razem z bazą na docelowym hoście. Nie wdrażaj do produkcji bez wyraźnej zgody właściciela.
10. Etap UI ze zrzutów coldz.pro jest ukończony: Member login → karta TimonConfigs → dashboard z avatarem, rzeczywistym statusem i kafelkami. Zweryfikowano lokalne HTTP, stany konta i responsywność. Następny etap z Astra Medium to końcowy przegląd bezpieczeństwa oraz testy prawdziwego OAuth/pobrań na HTTPS stagingu, opisane w punktach 3–4; nie buduj panelu ponownie.

Publiczna witryna i podgląd Hostinger nie były zweryfikowane zdalnie z powodu blokady proxy. Brak callable narzędzi Hostinger, a API GitHub GraphQL zwraca Forbidden. Kod jest na `main`; push do GitHub nie oznacza wdrożenia na hosting ani zatwierdzenia audytu. Publiczny odczyt coldz.pro również zablokowało proxy — handoff opiera się na zrzutach właściciela.
