## Shared interfaces

Root owns `class-tc-billing.php`, existing Checkout/Discord glue, plugin initialization, settings/admin/controller/webhook workers. Dependencies use these static methods:

- `TC_Billing::config(): array`: option `timonconfigs_billing`, defaults `mode=test`, `routing=legacy`, flags false; global keys `stripe_test_confirmed`, `migration_confirmed`, `legal_confirmed`, `role_sync_enabled`, `paypal_enabled`; mode-specific keys stored as `test_stripe_monthly_price_id`, `test_stripe_monthly_product_id`, `test_stripe_lifetime_price_id`, `test_stripe_lifetime_product_id`, `test_paypal_monthly_plan_id`, `test_paypal_monthly_product_id`, `test_paypal_webhook_id`, `test_discord_guild_id`, `test_discord_monthly_role_id`, `test_discord_lifetime_role_id` (same live_ prefix).
- `TC_Billing::setting(string $key, string $mode): string`: read mode-prefixed public setting. No caller-supplied URLs.
- `TC_Billing::secret(string $name,string $mode): string`: wp-config constant `TIMONCONFIGS_BILLING_{TEST|LIVE}_{NAME}`. Names `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `DISCORD_BOT_TOKEN`; Discord interactions public key constant `TIMONCONFIGS_BILLING_DISCORD_PUBLIC_KEY`.
- `TC_Billing::plan(string $plan): array`: immutable `plan`, `name`, `amount`, `currency=eur`, `interval=month|one_time`.
- `TC_Billing::display_price(string $plan): string`: new central EUR prices when direct routing active, preserved legacy prices while Upgrade.chat routing remains active; no browser/theme amount controls billing.
- `TC_Billing::mode_allowed(string $mode): bool`: test only local/development/staging; live only `TIMONCONFIGS_BILLING_LIVE_APPROVED===true` and confirmed migration/test settings. `::direct_enabled(): bool`; `::error(string $code,string $message): WP_Error`.

### Store (agent owns class-tc-billing-store.php)

WordPress prefixed dedicated InnoDB tables, private/non-REST; all dates UTC SQL datetime. `install():void`, `init():void` versioned schema. IDs for orders UUID36. APIs:

- `create_order(int $uid,string $discord_id,string $provider,string $mode,string $plan):array|WP_Error`; derive amount/currency from TC_Billing::plan; status=pending, created_at. Record consent separately via update_order allowlist.
- `order(string $id):?array`; `update_order(string $id,array $fields):bool|WP_Error` fields include checkout_id,customer_id,subscription_id,payment_id,status,cancel_at_period_end,next_payment_at,consent_at,consent_version (never allow rebinding uid/discord/provider/mode/plan/amount).
- `orders_for_user(int $uid,string $mode,int $limit=20):array`; `find_order(string $provider,string $mode,string $external_id):?array` matching trusted checkout/subscription/payment IDs. `entitlements(int $uid,string $mode):array`, `active(int $uid,string $mode):array` (status active AND lifetime/null end OR future valid_until). `entitlement(string $source):?array`.
- `upsert_entitlement(array $data):bool|WP_Error`: unique source, immutable uid/discord/provider/mode/plan once inserted; fields source,user_id,discord_id,provider,mode,plan,status(active|expired|revoked|disputed|pending),valid_until(null Lifetime or UTC monthly),external_id,order_id,customer_id,payment_id,last_invoice_id,cancel_at_period_end,next_payment_at,next_check_at. Protect competing independently valid sources.
- `enqueue_event(string $provider,string $mode,array $descriptor):array|WP_Error`; descriptor id,type,object_id,created (+optional order_id). Unique(provider,mode,id), status pending, attempts0, due now. Store bounded identifiers only, no raw bodies/tokens/emails. Duplicate returns existing row.
- `due_events(int $limit=10):array`; `event(int $id):?array`; `event_result(int $id,string $status,string $error='',int $retry_after=60):void`; status done/error/pending, attempts,next_attempt,redacted safe code. `apply_event(int $event_id,array $transition):bool|WP_Error` atomic order+entitlement+enqueue_sync+mark done. A transition without entitlement may update pending/failed order. Preserve existing valid paid_until on payment-failed/pending canonical state.
- `enqueue_sync(int $uid,string $mode):void`; `due_syncs(int $limit=10):array`; `sync_result(int $job_id,string $status,string $error='',int $retry_after=60):void`; `sync_state(int $uid,string $mode):array`; jobs unique user/mode, recompute desired state at processing time.
- `owned_roles(int $uid,string $mode):array`; `own_role(int $uid,string $mode,string $guild,string $role,bool $owned):void`. These record only exact VIP roles this module actually added; roles pre-existing at first observation are NEVER adopted automatically.
- `due_reconcile(int $limit=10):array` returns orders with canonical provider external IDs; `mark_reconciled(string $order_id,int $retry_after=3600):void`.
- `diagnostics(int $limit=20):array` events/jobs for admin, bounded safe error codes.
- `locked(string $key, callable $callback):mixed`: atomic expiring lease (CAS release only own nonce), WP_Error busy; never unsafe get+delete racing.

### Provider adapters (separate agents)

`TC_Billing_Stripe` / `TC_Billing_PayPal` public static APIs:

- `create_checkout(array $order):array|WP_Error` => id,url (pinned hosted checkout URLs), optional customer_id/subscription_id/payment_id. Browser amounts/provider IDs never used. Provider idempotency key derived from order UUID. Binding metadata/order custom_id uses exact stored order, WP uid and Discord ID.
- `verify_webhook(string $raw,array $headers,string $mode):array|WP_Error` => descriptor id,type,object_id,created. Stripe headers normalized lowercase, HMAC timestamp tolerance300s, multiple v1 accepted, mode matched. PayPal remote verification via pinned API, configured webhook ID and transmission headers; never download arbitrary cert_url. Unknown event types safely ignored with descriptor type.
- `reconcile(array $event):array|WP_Error`: fetch canonical provider object(s), do not trust webhook event arrival order. Return transition: order_id, order_fields(array safe fields), optional entitlement(array above). Only verified actual paid state activates. Check fixed expected product/price/quantity/currency and actual settled payment. Monthly valid_until from paid service period, cancellation preserves paid period. Failed renewal never extends access or instantly removes prepaid time. Full refund/current chargeback revokes affected source only; partial refund doesn't erase unrelated sources. Lifetime null expiration. Exact order provider/mode/Discord/WP ownership must match canonical metadata. Independent operator entitlements remain independent.
- `portal(array $order):string|WP_Error` for Stripe customer portal. PayPal portal may return pinned PayPal subscription management URL.
- `cancel(array $order):array|WP_Error`: Stripe cancel_at_period_end, PayPal stop future renewals. Preserve current prepaid end. Return safe provider result; root queues canonical reconciliation. NEVER derive access from return URL.
- PayPal only `capture(array $order):array|WP_Error` for approved Lifetime order; idempotent server call, actual entitlement still through verified canonical processing.

## Final integration notes

Latest main `ea566d4` was merged without replacing code. Store reads `active`, `entitlements`, `checkout_attempts`, `unresolved_recurring` and `owned_roles` propagate database failures as `WP_Error`; callers must not treat errors as authoritative empty coverage. `own_role` returns `bool|WP_Error` and remote mutations must check it. Existing unowned roles require manual review even when desired; never adopt them on retry. Worker `due_events`, `due_syncs` and `due_reconcile` accept an optional mode argument, filtered before LIMIT; the controller always passes its current mode. `apply_event` accepts a lease key to fence canonical results inside the SQL transaction. An uncertain pending checkout is retained across age/history windows; an old attempt without a provider ID needs reconciliation before any new POST. These safety decisions are covered by the final integration suites.
